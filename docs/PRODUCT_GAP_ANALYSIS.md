# Product gap analysis

Audited after the production-blocker pass. A capability is complete only when the repository does the thing and a test or a real call proves it. An adapter without credentials is not a connected account.

Readiness: **not production ready.** The decision loop, local semantic model, separate worker, and storage providers are implemented. Live ad accounts, a hosted always-on worker on serverless, a verified S3 bucket, and video generation are not.

## What is still not true

Meridian does not buy media. It does not invent competitor ads, publish receipts, or performance. Semantic retrieval is a local MiniLM model, not an external embeddings vendor. The worker and scheduler are real processes in this runtime. A serverless deploy does not run them between requests. S3 is a client, not a connected bucket, until `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, and `S3_SECRET_ACCESS_KEY` are set and a request succeeds. Calibration math does not move live thresholds. Logo comparison does not understand a logo that is only a small part of a photograph.

The proof is `src/lib/meridian/blockers.test.ts` together with `acceptance.test.ts`. Those tests are not a live ad account.
