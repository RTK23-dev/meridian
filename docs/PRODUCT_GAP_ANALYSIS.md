# Product gap analysis

Audited against the canonical Meridian loop, not against the presence of a screen. A capability is COMPLETE only when the repository does the thing. Typecheck and a green test are not enough. Providers that need an account stay blocked.

Readiness: **development ready, not production ready.** The decision loop works on evidence a person stores. Live ad accounts, neural embeddings, video, PDF extraction, and an external object bucket are not connected. The acceptance proof is `src/lib/meridian/production.test.ts` plus `src/lib/meridian/acceptance.test.ts`.

What is still not true: ad library, publishing, a live performance feed, video, PDF extraction, and semantic embeddings are not connected, and they do not invent results. Lexical similarity is not semantic understanding. The in-process worker is real for the preview database. It is not a separate always-on production daemon. Calibration does not move thresholds. The tests prove the loop on stored evidence. They do not prove a live ad account.
