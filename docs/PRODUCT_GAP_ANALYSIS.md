# Product gap analysis

Audited after the production-blocker pass. A capability is complete only when the repository does the thing and a test or a real call proves it. An adapter without credentials is not a connected account.

Readiness: **beta 0.1.0-beta.3; product paths are implemented, but external accounts and infrastructure must be configured for live operation.** The decision loop, local semantic model, JEV Research, Studio generation path, Meta Hypit video publishing, separate worker, and storage providers are implemented. This repository does not include connected ad accounts, a durable production bucket, or a hosted always-on worker.

## What is still not true

Meridian does not automatically activate campaigns or invent competitor ads, publish receipts, or performance. Semantic retrieval is a local MiniLM model unless an external embeddings API is configured and answers. The worker and scheduler are real processes; a serverless deploy does not run them between requests. S3 is not connected until configured and a request succeeds. Provider clients store external ids only after a provider response confirms them. Logo search is a PNG region hash, not a neural detector. Calibration math does not move live thresholds by itself.

The proof is `src/lib/meridian/blockers.test.ts`, `providers/readiness.test.ts`, and `acceptance.test.ts`. Those tests are not a live ad account.
