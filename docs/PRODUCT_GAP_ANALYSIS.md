# Product gap analysis

Audited after the production-blocker pass. A capability is complete only when the repository does the thing and a test or a real call proves it. An adapter without credentials is not a connected account.

Readiness: **beta 0.1.0, not a live media buyer.** The decision loop, local semantic model, Studio generation path, separate worker, and storage providers are implemented. Live ad accounts, a hosted always-on worker on serverless, and a verified S3 bucket are not connected from this repository.

## What is still not true

Meridian does not buy media. It does not invent competitor ads, publish receipts, or performance. Semantic retrieval is a local MiniLM model unless an external embeddings API is configured and answers. The xAI video adapter stores a clip only after bytes return. The worker and scheduler are real processes. A serverless deploy does not run them between requests. S3 is a client, not a connected bucket, until the S3 variables are set and a request succeeds. Provider clients will call Meta, TikTok, Google Ads, and Ad Library when credentials exist, and they store an id only when that call returns one. Logo search is a PNG region hash, not a neural detector. Calibration math does not move live thresholds by itself.

The proof is `src/lib/meridian/blockers.test.ts`, `providers/readiness.test.ts`, and `acceptance.test.ts`. Those tests are not a live ad account.
