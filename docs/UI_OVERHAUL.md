
## 0. The one-paragraph diagnosis

The backend is rich: market research, JEV decisions, opportunity ranking, studio, review, publishing, learning, jobs, alerts, usage tracking. The panel exposes it as long text pages. Every screen is a stack of bordered boxes with paragraphs, `toFixed(2)` numbers and internal vocabulary ("sample rule", "stored publisher id", "test:image"). There are no charts, tables, media players, toasts, dialogs, skeletons, dark mode or keyboard shortcuts. About 20 UI libraries are installed and **none are used**. Generated video cannot be played at all. The fix is not a repaint. It is a design system, a data layer, a restructured navigation, redesigned screens, and a few missing backend endpoints.

## 1. Rules(read before touching anything)

### 1.1 Do not break these product rules

Meridian's identity is honesty about what is connected and real. The new UI must keep it:

1. **Never invent data.** No fake charts, placeholder metrics, sample ads or "demo" numbers shown as real. Empty states say what is missing and how to fix it.
2. **Not connected stays visible.** A provider that is not connected must say so (`NOT_CONNECTED`, `HYPIT_NOT_CONNECTED`). Do not hide it, and do not show a green state.
3. **Role checks stay.** Keep `hasRole(role, "member" | "admin")` gating on every mutation button. Viewers get read-only UI.
4. **Server rules stay.** Do not change scoring, JEV, tenancy, auth, or provider logic while doing UI work. If a UI task needs new data, add a new server function and keep the old ones unchanged.
5. **Test-provider output stays labeled** (`test:performance`, "Fixture, not a camera recording").

### 1.2 Repo facts that will trip Codex up

Only `scripts/**/*.test.mjs` is globbed. | When you add a test file under `src/`, add it to the `test` script, or CI will never run it. ### 1.3 Working method for every phase

1. `npm ci` then `npm run dev` (port 8080).
2. **Screenshot first.** Use Playwright (already a dependency) to capture each screen you will touch at 390, 768 and 1440 px, light and dark when available. Save to `docs/ui-baseline/` (git-ignored if large). Do the same after.
3. Make the change in small commits.
4. Before finishing: `npm test && npm run typecheck && npm run lint && npm run build`. All four must pass. Paste the real output tails in the PR description. Do not write "should pass".
5. One branch and one PR per phase: `ui/phase-N-short-name`.
6. If something cannot be verified (no network, no database), say so explicitly.

## 2. What is actually wrong (verified in code)

### Structure and navigation
- `components/shell.tsx`: 10 flat sidebar links in one list with no grouping. The only links to Integrations and Settings in the whole app are inside the brand sidebar, and that sidebar renders only on `/brands/:id/*` pages. From the workspace home, Settings, Integrations and the new-brand page there is **no link to either** (only typing the URL works). The header's "Workspace" link points to `/`, the same place as the logo.
- No breadcrumbs, no brand switcher (you must go back to `/` to change brand), no global search, no command palette, no notification bell (`alerts-panel.tsx` is only reachable inside Settings and only for admins).
- `components/brand-nav.tsx` is a leftover stub that returns `null`, yet 18 places still render `<BrandNav />`. Delete the component and its imports once the new shell lands.
- Mobile: "Menu" is a text button toggling the sidebar. No bottom bar, no sheet.

### Look and feel
- Light only (`color-scheme: light`). No dark mode.
- Visual language is "paper and brass" boxes: `rounded-lg border bg-panel p-5` everywhere. `Panel` is the only container, used for everything from a KPI to a 40-line essay.
- Headings use the serif display font (Fraunces) for even small panels. Eyebrow labels (`text-xs uppercase tracking-widest text-brass`) appear on nearly every card, which makes everything shout equally.
- Buttons: 3 variants, no sizes, no icon support, no loading state beyond swapping text.
- Inputs: one style, `py-3 text-base` (tall), no inline validation, no prefix/suffix, no error styling on the field itself. Errors are one `<Notice>` at the bottom of the form.
- Only 8 `role=`/ARIA attributes across all screens. No tables anywhere (0 `<table>`).

### Data and state
- Every screen does `useEffect` + `useState` + manual `cancelled` flag (11 routes). `@tanstack/react-query` is installed and unused. Result: no caching, refetch-on-every-navigation, "Loading…" text instead of skeletons, and after each mutation the whole page state is replaced (`setSession(await ...)`) or reloaded (`await reload()`).
- `WorkspaceProvider` loads `bootstrap()` into context by hand; changing workspace calls `reload()` and blanks the page.
- No optimistic updates, no background refresh, no stale indicator, no retry button on errors (an error just shows red text and the page is dead).
- `useBusy` is a single pending flag per screen. In Studio, **one** `busy` disables every button while any one action runs.

### Specific screen problems
- **Home (`routes/index.tsx`)**: the same `recommendation(...)` sentence is rendered **twice** (under the title and again inside a "What is missing" panel). Brand cards show only "x% known" and a sentence. No KPIs, no activity, no health, no pending-work counts.
- **Brand overview (`brands/$brandId/index.tsx`)**: the page is mostly an identity edit form (6 inputs) with the useful pipeline status below it as paragraphs. Six panels each say one sentence ("No generation run is stored."). No progress visualization of the pipeline `market → research → opportunity → JEV → brief → studio → QA → review → publish → performance → learning`.
- **Opportunities**: ranked cards, but the score components (brand fit, history, market, novelty, reproducibility, saturation, risk) are a `dl` of numbers like `0.73`. No bars, no radar, no sort/filter, "Why this" is a text button that expands in place. Research ids are printed as comma-separated strings.
- **Studio (`studio.tsx`, 346 lines)**: the core product screen.
  - Generated images show at `h-24 w-24` (96 px). Video variants have **no `<video>` element at all**. There is no route that serves stored media bytes (`src/routes/api/` has only `auth`, `health`, `oauth`, `webhooks`). A produced Hypit clip cannot be watched or downloaded in the app.
  - Review buttons send hardcoded values: reject always sends `reasonCode: "too_similar"` and note `"Does not earn the angle."`; revision always sends `"Revise the opening. Keep the product."` Real reviewers cannot type a reason.
  - "Compare" two variants prints their prompt versions as a sentence. It does not show them side by side.
  - Provider names leak as UI options: `test:image`, `google:nano-banana`, `hypit`.
  - Everything is one scrolling page of panels: recommendation, clusters, whitespace, brief, generate form, variants, learning. There is no step flow.
- **Delete brand** uses `window.confirm`.
- **Copy**: heavy internal vocabulary: "sample rule", "stored publisher id", "generation run", "exploration, not a finding", "priors stay labeled as priors", "Score from evidence". Accurate, but written for the engineers.
- **Errors** are raw `error.message` strings from the server shown in red text.

### Missing screens (the backend already supports them)
- **Jobs / queue monitor**: the `jobs` table, `process_heartbeats`, and `/api/health` exist, but no UI shows job status, failures, retries, dead letters, or whether the worker and scheduler are alive.
- **Usage and cost**: `observability/usage.ts` summarizes tokens and cost by operation; nothing displays it.
- **Audit log**: `components/audit.tsx` is 19 lines and only shows a short recent list on Home.
- **Alerts center**: `alerts/actions.ts` has `getAlerts`, `acknowledgeStoredAlert`, `saveDeliveryTarget`; UI exists only buried in Settings.
- **Calibration, performance schedule, organization-learning opt-in and pattern sharing** (`getCalibration`, `proposeCalibration`, `decideCalibration`, `setPerformanceSchedule`, `setOrganizationLearning`, `sharePatternWithOrganization`) all exist, but only inside the 308-line `learning.tsx`, which also holds the charts-that-should-be and the manual performance form. Split them into their own screens or tabs (see phase 4.8 and phase 8).

## 3. Target design

### 3.1 Principles
1. **One job per screen, one primary action per screen.**
2. **Show state with visuals, not paragraphs**: badges, progress, charts, tables.
3. **Plain language first, technical detail on demand** (a "Details" drawer holds ids, checksums, prompt versions, JEV question rows).
4. **Everything long-running shows progress** and survives refresh (jobs are durable; read their status from the server).
5. **Honest empty states** that explain the next action and link to it.
6. **Keyboard and screen-reader complete.** WCAG 2.2 AA is the floor.

### 3.2 Visual direction (keep the brand, modernize it)

Keep paper/ink/brass as the identity but use them with restraint. Use the serif only for page titles (`h1`) and big numbers. Everything else uses the sans.

Notes for Codex:
- **Contrast must be measured, not assumed.** `src/lib/meridian/a11y/contrast.ts` and `scripts/a11y-audit.mjs` exist. Add a unit test that every foreground/background token pair meets 4.5:1 (3:1 for large text and UI borders).
- Keep old token names (`ink`, `paper`, `panel`, `line`, `muted`, `brass`, `danger`) as aliases during the migration so unchanged screens do not break, then delete the aliases in the last phase.
- Self-host fonts (`@fontsource-variable/inter`, `@fontsource-variable/fraunces`) instead of the Google Fonts `<link>` in `routes/__root.tsx`. That removes a third-party request and a layout shift.
- Dark mode: a `ThemeProvider` that reads `prefers-color-scheme`, lets the user pick Light / Dark / System in the user menu, stores the choice in `localStorage`, and sets `class="dark"` on `<html>` before first paint (inline script in the root document to avoid a flash). Note: this is plain browser storage and is fine for a normal deployment. The `color-scheme` meta must follow the theme.
- Density: default 14px base for tables and lists, 16px for forms on mobile (prevents iOS zoom).
- Motion: 120 to 200 ms, `prefers-reduced-motion` already respected in `styles.css`; keep that block.

### Phase 2: Data layer (React Query)

Goal: no more `useEffect` fetching, instant navigation, no blank pages after mutations.

Tasks
1. Create `src/lib/query/`: `client.ts` (a `QueryClient` with `staleTime: 30_000`, `retry: 1`, `refetchOnWindowFocus: true`), `keys.ts` (typed key factory: `qk.workspace()`, `qk.brand(id)`, `qk.studio(id)`, `qk.opportunities(id)`, `qk.market(id)`, `qk.reviews(id)`, `qk.library(id)`, `qk.learning(id)`, `qk.jobs()`, `qk.alerts()`), `hooks.ts` (one hook per server function: `useBrand(id)`, `useStudioSession(id)`, ...).
2. Mount `QueryClientProvider` in `routes/__root.tsx`. Replace `WorkspaceProvider` internals with `useQuery(qk.workspace())`; keep `useWorkspace()` returning the same shape so existing code compiles.
3. Wrap every mutation in `useMutation` with: `onSuccess` invalidating only the affected keys, a toast, and (where safe) optimistic updates (review approve/reject, dismiss opportunity, acknowledge alert).
4. Replace each `useEffect(... .then(setX))` in these routes: `brands/$brandId/{index,brain,market,intelligence,opportunities,studio,library,reviews,learning,products}.tsx`, `integrations.tsx`, `settings.tsx`. 11 places.
5. Per-action pending state: replace the global `useBusy` flag in Studio with each mutation's own `isPending`, so approving one variant does not disable unrelated buttons.

7. Route-level error boundary and `ErrorState` with retry. Route-level pending component with a screen-shaped skeleton.
8. Prefetch on link hover/focus for sidebar links.

Done when: navigating between two visited screens shows content instantly; approving a review updates the row immediately and rolls back on failure; no `cancelled` flags remain; `grep -rn "useEffect" src/routes` returns only non-fetch effects.

**4.5 Studio (`studio.tsx`) — the most important screen**

1. **Direction**: recommended opportunity card, alternatives, accept button.
2. **Brief**: readable brief (sections), "what changed since the last brief" diff, edit/regenerate.
3. **Generate**: form with provider cards (not raw option strings): "Image" (None / Test / Google Nano Banana) and "Video" (Hypit). Show connection state on each card and disable with a reason when not connected. Show daily/concurrency limit usage as a progress bar. Show estimated cost only when the provider returns one (keep that rule).
4. **Review**: variant gallery.

- Status badges (QA, review, creative status), progress for in-flight jobs, error with retry.
- **Review dialog** instead of hardcoded strings: approve / reject / request revision; reject shows a reason select (the server already has `reasonCode`; read the allowed codes from `jev` or `studio/features` and use them) and a required note; revision requires a note. Keyboard: `A` approve, `R` reject, `V` revision, arrow keys to move between variants.
- **Compare view**: two variants side by side with synchronized playback for video, plus a metadata diff (prompt version, model, QA answers).
