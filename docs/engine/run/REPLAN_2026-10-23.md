## Owner direction (2026-10-23)

1. Veo stays off. It is an adjustable setting, not a deleted route. Its default is off.
2. Budgets are not hard limits. A safe limit with an adjustable tolerance: a small overrun (one cent over) must not stop a video
   that is nearly done. Beyond the tolerance the run pauses and asks for approval. It never fails half-way for a few cents.
3. Nothing is hard-coded. Every budget, tolerance and model-policy value is a setting with an initial value, adjustable per
   workspace, per brand and per request.
4. The user can set a copy budget and a creative budget for the orchestrator (both optional). The orchestrator delegates the
   budget to its tools (text, image, video, voice) and plans ahead before it runs anything.
5. Per-creative attestation for music, footage and the AI label stays exactly as it is.
6. The orchestrator gets an up-to-date model brief: the best current models by cost and quality, latest preferred over older ones.
7. Decision points 3, 4 and 5 of the 2026-10-23 list are not touched: (3) the calibration bootstrap stays as it is (grades go to
   review until a brand has measured outcomes); (4) the plan-to-video bridge (D16 to D18) is not built; (5) paid ads (D14, D15) are
   not touched.
8. No paid-ads work. The Factory's paid path and paid publishing stay as they are.

## What the code does today (read on origin/main, 2026-10-23)

- `validate.ts` refuses a plan whose estimate exceeds `budgetUsd` (`validatePlan`, `planBudgetReason`).
- `execute.ts` pauses the run before any step whose estimate would take spend past `budgetUsd`. The pause is exact: no tolerance.
- `service.ts` `checkPlanCall` refuses the planning call when its hold (call plus one retry) exceeds the plan budget, and refuses
  when the workspace month would be exceeded.
- `run-budget.ts` opens the run's reservation for the remaining budget and refuses when nothing is left or the month would be
  exceeded.
- `budget/reserve.ts` and `budget/preflight.ts` (the brief path) pause in `cap` mode on any overrun. `warn` mode records it.
- The composer collects goal, format, your inputs, brand and one budget (default $2). No category budgets, no model policy.

## Blocks

- **B0 Setup.** Done. Worktree and install.
- **B1 Veo off and model policy.** A workspace policy (stored JSON on `orchestrator_settings`, additive migration) holds the
  disabled model families. Initial value: `google/veo`. The chooser and the route fallbacks skip disabled families. Adjusting the
  list re-enables. Tests: a disabled family is never chosen, even when it is listed and cheapest.
- **B2 Soft budgets.** One pure tolerance module (`budget/tolerance.ts`): tolerance = the larger of `percent` of the target and
  `cents`. The allowance is target plus tolerance. Used by: plan validation (within allowance is accepted with a note; beyond it the
  plan is flagged for approval, not refused); the executor (a step may start while spend stays within the allowance; beyond it the
  run pauses for approval); the planning call (a hold within the allowance is allowed); the run reservation and the month check (a
  shortfall within the allowance is allowed; beyond it the run waits for approval); the brief path (`reserve` and preflight in cap
  mode admit a hold within the allowance). Tests for each boundary, including one cent over.
- **B3 Category budgets and delegation.** The brief may carry `copyBudgetUsd`, `creativeBudgetUsd` and `voiceBudgetUsd`
  (optional). Copy is the text kinds (analysis, script). Creative is visual, video and avatar. Voice is voice. Unset categories
  are delegated under the total. The plan schema is unchanged; the brief carries the split and the planner is told it. The validator
  sums estimates per category and checks each sum against its category budget with the same tolerance. The executor enforces the
  category allowance per step as well as the total. Tests for each category, including delegation with no category set.
- **B4 Model brief.** A versioned brief (`src/engine/prompts/model-brief@1.md`) with the current candidates per capability: text,
  image, video (Veo excluded while the policy disables it), speech. Each entry has its live price basis, its release date from the
  public listing, and a quality note that cites its source or says the quality is unverified. The planner prompt moves to
  `orchestrator_plan@3`, which includes the brief and the budget split. Decision D9 is not resolved here; it is noted.
- **B5 Settings and inputs UI.** The composer gets the optional copy and creative (and voice) budgets next to the total, and a
  "copy a format" or "your own inputs" choice that sets which fields are required. A Settings panel shows the workspace policy: the
  tolerance, the disabled families (Veo on or off), and the initial values. Admin only, with role checks. Before and after
  screenshots in `docs/feature-screens/`.
- **B6 Documents.** CLAUDE.md working rule 3 and the Bible's budget wording change from "hard limits" to "soft limits with an
  adjustable tolerance and approval beyond it", recorded as the owner's direction of 2026-10-23. FACTORY.md, ROADMAP.md and
  PHASE_LOG.md are updated to match.
- **B7 Gates.** Targeted tests per block. Then `npm test`, `npm run typecheck`, `npm run lint` and `npm run build` once at the end,
  and a browser check of the changed screens on the dev server. The results go in RUN_STATE.
