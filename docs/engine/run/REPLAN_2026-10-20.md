# Replan, 2026-10-20

This replan follows the owner's direction of 2026-10-20. Where it differs from the earlier run plan (`RUN_PLAN`, written by another agent and never copied into this repo), this file governs. The earlier plan's five-agent roster, its fixed checkpoint times and its fixed model ids are withdrawn.

## Owner decisions

1. **One loop, one agent.** The lead works alone. No subagents, no workflows, no parallel agents.
2. **No fixed models.** The orchestrating model is chosen by the user. Each production model is chosen from the live OpenRouter catalog at run time. Nothing in the orchestrator names a model.
3. **The orchestrator scopes the build.** It takes the whole context (a viral format, the user's inputs, Meridian's brand and product data), draws the build as a graph of steps, and uses the engine's own tools for each step.
4. **Visible planning.** The build starts on a plain canvas. Each step appears as the orchestrator plans it and is connected to the steps it reads, in the style of a node-and-wire workflow editor.
5. **Surgical edits.** A change to one step re-runs that step and what depends on it, not the whole video. The end goal is a single shot tweaked and the video re-rendered from that point.
6. **Live runs and budgets are approved.** Budgets are hard limits: the run pauses before it would overrun, and never overruns.
7. **Checkpoint times may move.** Scope may shrink to keep a step's exit gate. Checkpoints are the lead's to move.
8. **Push between blocks.** Work lands on one branch, `run/factory-6h`, built from `main`.

## Built this session

All under `src/engine/orchestrator/`, using only the repo's existing zod v4 and the `contentHash` helper. No new dependency.

- `contracts.ts`: the plan (`orchestrator-plan@1`), ten step kinds, a live model reference, and the step events. Every schema is strict.
- `catalog.ts`: parses a live catalog snapshot. A bad row is dropped with its reason; a snapshot with no list is refused.
- `fixtures/openrouter-catalog-2026-10-20.json`: recorded on 2026-10-20 from OpenRouter's four public listings. 585 entries: 456 text, 30 video, 63 image, 36 speech. Trimmed to id, name, kind and modalities. Prices are fetched live at run time, not stored here.
- `fixtures/sample-plan.json`: an authored example plan for a viral-format remake, with 10 steps and an estimate of $1.13 against a $2.00 budget. It is written by hand, not model output. Its model ids are live ids from the snapshot.
- `validate.ts`: checks a plan before anything runs. It checks catalog membership, that each model's kind fits its step, that model-free steps have no model, that every paid step has a model and an estimate, the budget total, dependencies and cycles. It returns every reason.
- `dirty.ts`: surgical edits. The stale set is a changed step plus everything downstream. A step's cache key hashes its kind, model, params and the keys it reads. Title and wording are excluded.
- `execute.ts`: runs a plan with handlers passed in, so it calls no provider itself. A step with no handler is `not_connected` and is never reported as done. A step that throws is `failed` and its readers are `skipped`. A step that would overrun the budget is `paused` and nothing after it runs. Cache hits cost nothing.
- `layout.ts`: places steps in columns by the steps they read, stacks each column in plan order, and draws each edge as a curve.
- `replay.ts`: the canvas state after the first N events of a run.
- `src/components/content-factory/orchestrator-canvas.tsx`: the canvas. Steps pop in and lines draw in, using keyframes in `src/styles.css`. `NOT CONNECTED` is shown as-is. The global reduced-motion rule cuts the animation.

Tests: 52 orchestrator tests (contracts, catalog, validation, surgical edits, executor, layout, replay, and a scan that fails if any orchestrator source file names a model id).

## Not done, and why

1. **Live runs.** No `OPENROUTER_API_KEY` is set in this environment, so no paid call has been made. The owner's approval covers live runs and budgets, but the key has to be supplied through the environment. Until then, every paid step reports `not_connected` through the gateway.
2. **Fixed ids in the legacy pipeline.** `src/engine/config/routes.ts` still hard-codes nine model ids and `src/engine/config/prices.ts` has seven price keys, and 53 test files refer to them. The orchestrator path does not use them. Removing them means the gateway's `route()` takes the orchestrator's live choice for every role call, and the tests move with it. That change touches the gateway contract, so it is the next task and was not done in a rush here.
3. **The canvas is not on a screen yet.** Nothing stores a plan or streams its events. The next step is a Factory API route that stores a plan and streams the events, and a Studio screen that mounts the canvas.
4. **The orchestrator model picker is not built.** The plan carries the chosen model's id, and validation checks it against the live text list. The picker that lists those models and records the user's choice is not written.
5. **Surgical re-render is not wired to HyperFrames.** The stale set and the cache keys exist. Connecting a changed step to the compose and render steps is not done.
6. **No browser check of the canvas.** It type-checks and lints, but I have not looked at it on a screen. There are no screenshots.
7. **Open owner decisions, not resolved in code:** artifact storage (S3 versus Postgres and Drive; no S3 was added), Veo (no provider exists in the repo, and PR #45's notes say its preview shuts down on 2026-10-22), and Hypit. The Bible's live-run acceptance test has not been run.
8. **PR #45's UI screens are not on `main`.** The Studio screens sit on a deleted base branch. Restoring them is an owner decision.
